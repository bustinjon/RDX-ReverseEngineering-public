## Supported synthetic ordering and deliberate stop point

Explicit transport-ready → raw version request/response → explicit PLAINTEXT_SIMULATION_BYPASS → HU AuthComplete → phone discovery request → HU capability response → explicit service/channel binding and open → video channel available → observed setup request → **UNKNOWN_MEDIA_TRANSITION**.

The bypass is neither a handshake nor evidence TLS established. Discovery direction remains HU-advertises/phone-requests. Negative discovery-entry tests stage malformed local HU advertisements; they do not invent phone advertisements.

No additional video-configuration-response, readiness, focus-granted, video-start acknowledgment or media-running step is asserted. Start already carries a config index in the known base schema; that is not proof the setup scalar is also an index. Honda's sourceVideoConfigCallback establishes a local selected-index callback, not a separate wire message. The library therefore does not select a phone-negotiated configuration or enqueue video data from these synthetic observations.
