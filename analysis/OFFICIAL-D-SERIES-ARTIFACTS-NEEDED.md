# Official D-series artifacts that most improve safety

2026-10-22. Exact target2021 RDX D.1.6.4. Local inventory only; no website, dealer, other owner, vehicle service or network source contacted. No downloads/updates/flash operations. **A 2022+ receiver is optional code-comparison evidence and is not a dependency.** Cross-flashing is not part of this plan.

The highest-value item is a **supported recovery procedure paired with its applicable authentic media**. An image without a usable writer/entry path is not recovery; a procedure without the right image/keys is incomplete. Existing local `full-system` is a partial file dump, not an authenticated filesystem/partition image.

## What is already preserved and should not be requested again

- Current AA APK and both offline candidates; getVideoMode/protocol/render analysis, exact DEX patches and original signer evidence.
- Seven current updater/service package directories, two Diagnostics native-link target contents, public OTA root and package/version/UID/signature inventories: [current stack](current-update-stack/README.md).
- Matching framework/services code for PackageManager, Zygote/WrapperInit and Android recovery APIs; earlier native updater libraries remain separately identified historical artifacts.
- Historical mount/partition-count/kernel/properties/context captures. These are useful inputs but are not full images, actual init content, a decoded effective policy, private PMS state or a restore demonstration.

Private OEM signing keys are not needed or requested. No VIN/configuration modification, developer loading, boot entry or live update should be used to acquire these materials under this pass. Obtain existing original files or legitimately accessible official material first; network research requires separate authorization.

## Minimum decision-changing bundle

For the present vehicle, the most useful next bundle is: (1) applicable OEM recovery instructions/media; (2) exact-current boot/environment/utility/partition/startup evidence; (3) complete current AA/native/state baseline and an actual one-shot execution entry. If only normal PackageManager deployment is available, add an authentic compatible AA component/catalog plus its supported update-removal path. None of these depends on obtaining an F-series receiver.
