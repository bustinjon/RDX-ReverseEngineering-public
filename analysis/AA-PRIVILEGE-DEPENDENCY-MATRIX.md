# Privilege dependencies: Honda clone versus independent receiver

Exact target D.1.6.4/API22/ARMv7. **Application identity, Android permissions, SELinux and protocol authentication are separate checks.** A signature&#124;system permission can be granted by matching its owner signature or an accepted system-package route; it does not necessarily require exactly UID1000. Conversely, merely choosing UID/domain names does not grant it. New prototype requests neither shared UID nor any Android permission.

`No` below means the minimum video/diagnostic design does not need that privilege. `Conditional`/`Unknown` is not a proven denial. OEM integration requirements are individually scoped; not every Honda API requires a Honda signature.

## First-video essentials versus full integration

L1 needs only an ordinary Activity/Surface and optional MediaCodec inspection. L2 adds the native library/ABI/dependencies and local protocol credentials. L3–L6 add normal USB grant, an exclusive projection interface, native protocol framing/service discovery and public decoder/Surface access. Additional standard protocol endpoints may be necessary for phone acceptance; this is not an argument for importing privileged OEM integration.

OEM source selection, amplifier/audio/VR/call integration, NavigationService, startup coordination, vehicle-state subscriptions, launcher icons, reset daemon, Bluetooth pairing and corrected TTI can be omitted from the first video proof. A naive clone's first failure is not established without running it: it could occur in class/resource loading or an early protected service call. A **concrete** known protected boundary is MediaSourceManager's MEDIA_CONTENT_CONTROL check if that selection method is invoked. The minimal app never invokes it.

## Narrow boundaries, not a blanket UID conclusion

The earliest concrete data-access check is UsbSettingsManager.checkPermission: absent a grant it throws `User has not given permission to device`. The narrow remedy is an ordinary per-device grant, not UID1000. Next is an interface claim: stock may own it, and permission does not solve ownership. A future effective-policy denial would need its exact AVC/class/permission before deciding whether any narrow bridge is needed.

No observed/traced dependency currently proves a system UID, Honda APK signer or system_app domain is mandatory for the **minimum native video core**. This remains a feasibility conclusion, not demonstrated phone playback. See [transport trace](GAL-TRANSPORT-TRACE.md), [architecture](CUSTOM-RECEIVER-ARCHITECTURE.md) and [bounded first test](PARALLEL-AA-FIRST-LIVE-TEST.md).
