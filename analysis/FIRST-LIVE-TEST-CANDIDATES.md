## Evidence and logs required for any later decision

1. Recovery gate appropriate to the **largest possible** state change, not only intended Java values. Verify independent control survives AA failure and can perform cleanup without the modified component.
2. Current stock AA/native hash+mode/label/link baseline; consistent PMS/update state if touched. Save exact prior wrapper values/mount topology if relevant. Historical PID2442 must not be reused as a future live target.
3. Implement and inspect the hook locally; prove only Candidate A fields differ and no auto-reinjection/persistent settings/package/catalog writes exist. Check ART/inlining and GAL initialization timing.
4. Define one-shot abort/cleanup and stock relaunch before starting. A later root path additionally needs proven privilege acquisition/release and recovery; this pass does not supply it.
5. Capture bounded pre/post logcat and existing service/package/display observations using previously authorized **read-only** methods only when a later collection is approved. Key events: advertised/selected config index, resolution enum/margins/density/fps, sourceVideoConfig callback, H264/MediaCodec errors, surface/viewport and renderer scale. Logging itself does not authorize starting/changing AA.
6. Success requires decoded active content at expected geometry without clipping/aspect errors. An offered mode alone is not successful playback. Touch input must be separately checked against actual display/TTI dimensions; no blanket success claim from a screenshot.

**Stop decision:** no root or modified-AA live test should proceed. The next useful work is obtaining the missing **same-platform recovery/startup artifacts** and auditing a real bounded execution entry; a 2022+ receiver is optional bonus evidence.
